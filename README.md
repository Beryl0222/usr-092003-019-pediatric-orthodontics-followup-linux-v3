# 儿童矫治器制作与交接后端

把数字印模校验值、医生处方版本、加工参数、材料批次、技师复核、试戴结论、
交付说明、监护确认与后续异常串成**每件器械的完整履历**，并约束跨院复诊、
处方变更与批次召回中的责任边界。

- 事实只追加、不覆盖：所有制作事实以事件形式进入仅追加日志，终止/返工/继续使用
  只会追加裁决事件，已经发生的排产、投料、复核等事实始终保留可反查。
- 系统只提示风险与受影响范围，不替医生作临床判断（过敏结论必须由医生记录）。
- 数据最小化：加工方只拿到完成制作所需数据；影像与身份材料不随普通物流单外泄。

## 运行

```bash
python3 service.py --check                 # 基础自检
python3 service.py --port 8000             # 内存存储启动
python3 service.py --event-log ledger.jsonl # JSONL 持久化，重启后履历完整重建
python3 -m unittest discover -s tests -v   # 46 项测试
```

健康检查：`GET /health`（无需身份头）。

业务接口通过请求头标识操作人：`X-Actor-Id`、`X-Actor-Role`、`X-Org-Id`（角色：
`prescribing_doctor` / `receiving_doctor` / `technician` / `fabrication_admin` /
`clinic_admin` / `guardian`）。错误返回稳定的类型名与 HTTP 状态码
（403 授权、404 不存在、409 冲突/身份待确认、422 校验失败）。

## 关键规则

### 数字印模与身份
- 扫描以 `(algorithm, checksum)` 唯一归档；**重复上传返回同一扫描，绝不生成两件器械**。
- 同校验值扫描被指向不同患者时进入身份隔离（409），转人工确认，禁止据此建件。
- 姓名转写差异（如「张小明 / ZHANG Xiaoming」）只登记进人工确认队列，不自动并档；
  确认前阻断建件。
- 家长手机里的照片（`kind=photo`）只能参考，不能作为制作依据；
  `POST /devices/{id}/verify-scan` 用校验值比对原件，不一致时明确提示不得照旧重做。

### 制作履历
扫描 → 处方（不可变版本）→ 排产（加工参数）→ 材料批次 → 开工 → 技师复核
→ 成品 → 试戴（医生结论）→ 交付说明 → 监护人确认。未复核通过不能报成品，
未试戴通过不能交付。`GET /devices/{id}/history` 可反查任一器械采用的扫描、
处方版本、材料批次、制作人员、复核人、试戴医生与监护确认。

### 处方变更的批准责任
变更按**当前所处阶段**给出允许裁决，裁决与全部批准人留痕：

| 变更发生阶段 | 允许裁决 | 批准责任 |
|---|---|---|
| 排产前 | 终止 / 返工 / 继续使用 | 医生 |
| 排产中～复核 | 终止 / 返工 / 继续使用 | 医生 + 加工方负责人 |
| 成品 / 试戴 / 交付后 | 终止 / 继续使用 | 医生 + 门诊负责人（双签） |

- 返工：变更快照成为新的处方版本，可重新排产；旧生产版本与材料批次仍保留在履历。
- 继续使用：成品后必须填写书面理由，现行处方版本不变。
- 终止：旧件标记终止，不能再推进任何制作动作；重制需医生显式按原扫描建新件并挂
  `remade_from`（同校验值、新履历），防止已调整过的设计被误用。

### 异常处置（带期限，只提示风险）
`loss` 7 天、`damage` 5 天、`allergy_suspected` 3 天、`batch_recall` 10 天，
自登记起算，逾期派生为 `overdue`（采取处置不重置期限）。过敏疑点结案必须附带
医生的临床结论。批次召回锁定同批次**在役**器械范围，逐件生成独立处置单，
各接诊医生分别作出处置结论，系统不给统一医学结论。

### 授权视图与交接
- `GET /devices/{id}/work-order`：加工方视图，只有处方、参数与扫描校验值
  （影像本体走受控调取，不随单下发），无患者姓名与监护人信息。
- `GET /patients/{id}/clinic-view` / `guardian-view`：接诊机构与监护人按授权
  查看交付与处置进度；监护人视图不含加工参数。
- `GET /devices/{id}/shipping-label`：普通物流单去标识化，显式声明不含影像
  与身份材料。
- 换院交接（`POST /patients/{id}/handovers` … `accept/reject`）：快照全部未结
  异常，**责任人和原截止时间原样带走、不重新起算**；接收机构确认后获得查看授权，
  未解决异常始终可追到责任人与截止时间。
